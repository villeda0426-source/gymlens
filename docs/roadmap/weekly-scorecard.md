# SpotLift Weekly Scorecard

Reporting rule: use a fixed Monday–Sunday window. Record the data source and extraction time. Use `N/A — not yet measured` for missing data; never substitute zero.

## Success targets

Targets are provisional until two clean baseline weeks are available.

| Domain | Metric | Initial target | Why it matters |
|---|---|---:|---|
| North star | New users completing first workout and seeing/saving next recommendation within 72h | ≥25% | Measures the complete product promise |
| Activation | Onboarding completion | ≥40% | Detects early friction |
| Activation | Median time to first useful result | <2 minutes | Beginner confidence must arrive quickly |
| Coaching | Plan creation success | ≥95% | Core Coach reliability |
| Coaching | Full-plan feedback → next-plan success | ≥90% in controlled tests | Validates continuity |
| Reliability | Crash-free sessions | ≥99.5% | Release health |
| Reliability | Critical API availability | ≥99.5% | Product usability |
| Reliability | Coach p95 response time | Establish baseline, then target | Avoid premature target setting |
| Retention | D1 / D7 / D30 | Establish baseline | Indicates repeat value |
| Economics | AI cost per activated user | Establish baseline | Sets free-tier and pricing limits |
| Growth | App Store product-page conversion | Maintain or improve verified baseline | Store efficiency |
| Learning | User observation sessions | 10 in first sprint | Grounds decisions in behavior |

## Baseline known before this sprint

Historical App Store Connect window through August 14, 2026:

- 322 impressions
- 100 product-page views
- 23 first-time downloads
- 6 redownloads
- 16 updates
- 14.3% reported daily-average conversion rate

These values are historical context, not the build 43 baseline. Retention and version-level crash data were below Apple's reporting threshold at that time.
